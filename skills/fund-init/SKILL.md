# /fund-init — 初始化基金申请项目

**规格**：`~/.claude/skills/shared/FUND-PROTOCOL.md`（下称"协议"）。开始前先读协议第 1、3、4、5、6 节。

**输入** `$ARGUMENTS`：
- 无参数 → 新申模式，从选题方案读选题
- `重申 {前序项目文件夹名}` → 重申模式

全程中文。

## Step 1：读选题来源

**新申模式**，来源按顺序找：
1. `$ARGUMENTS` 里给出的选题方案路径
2. `$FUNDINGS/_drafts/选题方案_*.md` 中最新的一份（`ls -t | head -1`），AskUserQuestion 确认是否用它
3. 都没有 → 提示先跑 `/fund-mine`；用户坚持直接建，则逐项询问申请人代码、基金档案、年度、题目、研究方向

**重申模式**：
1. 读 `$FUNDINGS/{前序项目}/FUND.md`。阶段不是 `rejected` → 停止并说明（只有未中的项目能重申）。
2. 申请人代码、基金档案沿用前序卡片；年度询问用户（通常为前序年度 +1）；题目先沿用，Step 6 再确认是否修改。
3. 有新的选题方案（`_drafts/` 里该申请人、该档案的最新一份）时，AskUserQuestion 是否合并使用。

## Step 2：确认项目信息

读 `_profiles/{档案}`，从中取交付类型、正文结构、匿名要求、申报窗口。AskUserQuestion 一次确认：

```
1. 申请人：{代码}（{姓名}）
2. 基金档案：{档案}　年度：{年度}
3. 项目文件夹：{年度}_{代码}_{基金简称}
4. 题目：
5. 交付类型：{档案给出的值；多个值时请用户选定}
6. 截止日期：{按档案申报窗口推断，请用户核对}
7. 拟申请经费、研究周期（不知道写"待填"）
8. 项目组成员（不知道写"待填"）
```

申请人代码不在协议第 2 节登记表里 → 停止，提示先登记。

## Step 3：建项目文件夹

路径：`$FUNDINGS/{年度}_{代码}_{基金简称}/`

- **不存在** → 新建。
- **已存在且没有 FUND.md**（用户已经把官方通知、模板放进去）→ 就地初始化：只新增文件，**不移动、不覆盖**已有文件。
- **已存在、有 FUND.md、但没有 CLAUDE.md 和 `03_正文/`**（只建了卡片，如 /fund-hub backfill 补的卡）→ 就地初始化：卡片里已有的值作为 Step 2 的预填，Step 5.1 只补全"待填"字段，不覆盖已有值。
- **已存在且有 FUND.md 和 CLAUDE.md 或 `03_正文/`** → 停止，提示该项目已初始化；要改信息直接编辑 FUND.md。

按协议第 5 节建全八个子目录：`01_官方文件/`、`02_文献/`、`03_正文/`、`04_图表/`、`05_交付稿/`、`06_提交版/`、`07_评审与自检/`、`08_参考材料/`。用户已放进项目根目录的官方通知、模板，移入 `01_官方文件/`（移动前列出清单，经用户确认）。

## Step 4：从模板和档案生成章节规划

先读**当年官方模板原件**（`01_官方文件/` 里的申报书、活页 .doc/.docx）：

```bash
python3 -I "$FUNDINGS/_scripts/docx_template_map.py" "{模板文件}" > "01_官方文件/模板结构_{模板名}.md"
```

模板里的栏目标题和提示语就是官方提纲，优先于档案的"正文结构"；两者不一致时列出来请用户裁定（多半是档案过时，裁定后提醒用 /fund-hub profile 更新档案）。交付类型为 system、没有 Word 模板时，以通知或系统栏目截图为准。

再把提纲拆成 `03_正文/{NN}_{章节名}.md` 列表。每章确定：

- **文件名**：两位编号 + 档案原标题的简写，如 `01_选题.md`、`02_研究内容.md`
- **角色**：按协议第 5 节的角色词表标注（如 `立项依据`、`目标内容+创新点`）
- **字数上限**：档案写了就照抄；档案只给总字数或页数时，按章节分量提出分配建议
- **状态**：`待写`

只给表格栏目、不写正文的项（经费、基本信息、成员表）标角色 `表格`。

把列表展示给用户，AskUserQuestion 确认或调整（合并、拆分、改字数）。**章节以官方模板和档案为准，不套用其他基金的结构。**

## Step 4.5：申报约束（写作协议，动笔前必须确认）

按协议第 5 节"CLAUDE.md 的申报约束"格式，生成六块内容，分三次 AskUserQuestion 确认。确认后写进 CLAUDE.md，后续所有写作 skill 和 agent 只读这一节。

**1. 硬限制**：从模板说明行、通知、档案 `## 篇幅与格式` 逐条摘出总字数、页数、图片、参考文献、前期成果条数、匿名、周期，以及其他计数限制，每条写原文出处。能计数的填"脚本键"。各来源不一致时取最严的，并请用户裁定。

**2. 官方提纲**：模板每个部分的原文逐字照抄，拆成必答项（如"1.选题：选题的意义和价值，本课题国内外研究现状述评"拆成"意义和价值""国内外研究现状述评"两项）。每项写定：
- 文件，以及正文里要用的小节标题；
- 字数预算和图片预算。

预算规则：
- 合计不超过硬限制，字数留 5%–10% 余量。表头、参考文献列表计入总字数时，要单独留出。
- 图片优先给技术路线图和研究框架图。
- 参考文献有项数上限时，写明哪一章用多少条。比如限 10 项时，现状述评只能靠这 10 条撑起来，要在这里先定下来。在第 2 块表格末尾加一列"引用"。

**立项依据（选题意义、研究现状）类的必答项，默认再细分成下面几行**，每行有自己的小节标题和预算：
- **意义和价值**：研究背景 → 问题提出（从背景过渡到本选题）→ 理论意义 → 实践价值。研究背景和问题提出可以合成一个小节。
- **国内外研究现状述评**：国内研究现状 → 国外研究现状 → 研究述评。
  - 国内、国外两节按同一组研究脉络展开；
  - 研究述评写已有贡献、不足和本课题的切入点，不引新文献；
  - 国内、国外谁在前，默认国内在前，用户可以调换。

模板本身已把这些项分开列出时，照模板。

**3. 表格栏位**（交付类型含 word / word-macro）：按 `01_官方文件/模板结构_*.md` 的第 4 节，把每个"待填""勾选""说明+正文区"格子对应到要填的内容和来源（FUND.md、哪个 03_正文/ 文件）。注明不得改动的部分：行列数、合并单元格、列宽、说明文字。

**4. 排版规范**：表格每一行是一个元素，每个元素定下字体（中文 / 西文）、字号、加粗、行距、段前段后、缩进、对齐、编号格式。
- **模板规定了的照抄**，依据写"模板"。
- **模板没规定的**，按下面的默认值提出，依据写"自定"。
- 默认值：

  | 元素 | 字体 | 字号 | 加粗 | 行距 | 段前/段后 | 缩进 | 对齐 | 编号 |
  |---|---|---|---|---|---|---|---|---|
  | 一级标题 | 黑体 | 与正文同号或大半号 | 是 | 同正文 | 6pt / 0 | 无 | 左 | 一、 |
  | 二级标题 | 宋体 | 同正文 | 是 | 同正文 | 0 / 0 | 首行 2 字符 | 左 | （一） |
  | 三级标题 | 宋体 | 同正文 | 是 | 同正文 | 0 / 0 | 首行 2 字符 | 左 | 1. |
  | 正文 | 宋体，西文和数字用 Times New Roman | 模板正文字号，未规定用小四 | 否 | 模板值，未规定用 1.5 倍 | 0 / 0 | 首行 2 字符 | 两端对齐 | — |
  | 图题、表题 | 宋体 | 比正文小半号 | 否 | 单倍 | 3pt / 3pt | 无 | 居中 | 图1、表1 |
  | 表内文字 | 宋体 | 五号或小五 | 表头加粗 | 单倍 | 0 / 0 | 无 | 居中 / 左 | — |
  | 参考文献 | 宋体 | 比正文小半号 | 否 | 同正文 | 0 / 0 | 悬挂 2 字符 | 两端对齐 | [1] |

- **加粗与层级规则**：最多三级标题，不跳级。正文加粗只用于段首论点句或关键概念首次出现，每段至多一处。不用下划线、斜体、彩色字。
- **页数预估**：有页数上限时，按"正文字数 ÷ 每页容量 + 每张图约 1/3 页 + 表头"估算并写进来。每页容量按版心、字号、行距算：A4、五号、1.25 倍约 1700 字/页；小四、1.5 倍约 1000 字/页。预估超页时，先压行距或改字号，与用户商定后再写定。

**5. 文献预算**：参考文献的总数、中英比例、各小节分配、期刊门槛、年份要求。默认值见 /fund-lit Step 1，**每个项目都要用户确认**，不能直接沿用默认值。
- 总数不超过第 1 块的参考文献上限。
- 各小节分配要和第 2 块里立项依据各行的"引用"数一致。

**6. 变更记录**：写一行"YYYY-MM-DD 初始确认"。

三次确认的顺序：
1. 硬限制 + 官方提纲（含预算）+ 文献预算；
2. 表格栏位；
3. 排版规范。

交付类型只有 latex 时，第 3 块写"无"。第 4 块写成模板 class 的设置要求，不另定字体。

## Step 5：写文件

### 5.1 FUND.md

按协议第 3 节字段顺序写入。申请人 `{代码}（{姓名}）`；角色：代码为 zy 写"申请人"，否则写"协助"（zy 同时是项目组成员时写"项目组成员"）；项目组成员取 Step 2 的答案；阶段 `init`；结果 `—`；提交日期写 `截止 {日期}`；正文正本写 `03_正文/`（交付类型含 latex 时写 `03_正文/main.tex`）；提交版写 `06_提交版/`；前序申请：重申模式写前序文件夹名，否则"无"；后续申请"无"；评审意见"待填"；`## 复盘` 写"待填"。

### 5.3 章节骨架

每个 `03_正文/{NN}_{章节名}.md`：

```markdown
# {章节标题（照抄模板原标题）}

<!-- 角色: {角色} -->
<!-- 字数上限: {N} -->
<!-- 图片预算: {N} -->

## 写作要点

{结合 选题方案.md 和档案评审要点，列 3–5 条，写具体，不写模板话}

---

<!-- 正文从此开始 -->

## {申报约束·官方提纲里本文件的第 1 个小节标题，按排版规范的编号格式}
<!-- 必答项: {必答项}；字数 {N}；图片 {N} -->

## {第 2 个小节标题}
<!-- 必答项: …… -->
```

小节标题必须和 `## 申报约束` 第 2 块逐字一致，check_limits.py 靠它核对必答项是否写到。

### 5.4 选题方案.md

Step 1 用到的选题方案若引用了 `_drafts/` 里的 `立项分析_*.md` 或 `题目对标_*.md`（/fund-mine 在项目建立前生成的），一并 `mv` 到本项目 `08_参考材料/`，并把选题方案里的路径改成新位置。

把 Step 1 用到的选题方案复制为项目根目录 `选题方案.md`（只此一份，不再另存 idea.md 副本）。重申模式且没有新选题方案时，用前序项目的 `选题方案.md`；前序没有就根据前序正文生成一份精简版。

### 5.5 03_正文/main.tex（仅交付类型含 latex）

```bash
TEMPLATE_DIR=~/.claude/skills/fund-init/templates
# 档案为 NSFC 系列用 nsfc.tex.tmpl，其余用 provincial.tex.tmpl
cp "$TEMPLATE_DIR/{模板}.tex.tmpl" 03_正文/main.tex
cp "$TEMPLATE_DIR/latexmkrc.tmpl" 03_正文/latexmkrc
```

用 perl 替换 `{PROJECT_SLUG}`、`{PROJECT_TITLE}`、`{APPLICANT}`、`{AFFILIATION}`、`{PROPOSAL_DATE}`（主 agent 先 export 这些变量）。再把模板里的 `\section{}` 改成与章节规划表一致的标题和顺序，每节下留占位注释 `% 本节正文待灌入自 03_正文/{NN}_{章节名}.md`。`02_文献/{slug}.bib` 建空文件，main.tex 里写 `\addbibresource{../02_文献/{slug}.bib}`（模板已写好，替换 slug 即可）。

交付类型不含 latex 时不建 main.tex，`02_文献/{slug}.bib` 仍然建（引用管理用）。

### 5.6 官方模板

档案"来源文件"列出的本年度官方模板如果在别的项目里，复制一份到本项目 `01_官方文件/`（不移动原件）。

## Step 6：重申模式的额外工作

1. **继承正文**：
   - 前序有 `03_正文/*.md` → 按新章节规划逐章复制为起点，章节对应不上的部分放进 `08_参考材料/前序正文_未归位.md`。
   - 前序只有 Word 或 PDF → 用 `textutil -convert txt`（.doc/.docx）或 `pdftotext -layout`（.pdf）把提交版转成 `08_参考材料/前序正文.txt`，再按章节拆进各 `03_正文/*.md` 的正文区，开头标注 `<!-- 继承自 {前序项目}，待按修改清单修改 -->`。
   - 前序是 LaTeX → 复制前序 `03_正文/main.tex` 到 `08_参考材料/前序_main.tex`；交付类型仍为 latex 时，以它代替模板作为本项目 `03_正文/main.tex`。
2. **修改清单**：读前序 `07_评审与自检/评审意见_*.md`、FUND.md 的评审意见和 `## 复盘`，写 `07_评审与自检/重申修改清单.md`：

   ```markdown
   # 重申修改清单（前序：{前序项目}）

   | # | 评审意见原文（或复盘要点） | 问题归类 | 修改动作 | 涉及章节 | 状态 |
   |---|---|---|---|---|---|
   ```

   前序没有任何评审意见和复盘时，清单只写一行"无真实评审意见，修改方向由用户提供"，并 AskUserQuestion 请用户给出上一轮自己认为的问题。
3. **题目**：AskUserQuestion 确认沿用还是修改题目（同一基金重申，题目改动不宜过大）。
4. **回写前序卡片**：把前序 FUND.md 的"后续申请"改为本项目文件夹名。这是 /fund-init 唯一会改的其他项目文件，改之前告诉用户。

## Step 7：收尾

1. 运行 `python3 "$FUNDINGS/_scripts/build_portfolio.py"`；读 PORTFOLIO.md 的"跨申请人检查"和"命名问题"，有内容就报告。
2. 下一步提示运行 `/fund-lit`：按文献预算找文献，建文献池。立项依据要以文献池为骨架，所以文献在大纲之前做。阶段由 /fund-lit 入场时写成 `literature`。本子没有研究现状类章节、文献预算为 0 时，提示直接运行 `/fund-outline`。
3. 输出：项目路径、交付类型、章节数、申报约束要点（硬限制、图片和字数预算、页数预估）、截止日期与剩余天数、重申模式下修改清单的条数。

## 注意事项

- 不修改源项目和素材库的任何文件。
- 文件夹名必须符合协议第 1 节；用户给的名字不合规时，提出合规名字并确认。
- 截止日期少于 30 天时，在每次输出的第一行提醒剩余天数。
