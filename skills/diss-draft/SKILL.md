# /diss-draft — 学位论文中文正文撰写

## 定位

在 `/diss-init` 搭好章节骨架（含三级标题、字数分配、内容来源标注）后，逐章逐节撰写学位论文的中文正文。**核心任务是扩写而非翻译**——将英文小论文（~10,000 words）扩展为符合中国学位论文规范的中文长文（~37,000 字）。

**架构**：主 agent 逐节调度 → `sci-writer-zh` agent 生成中文学术文本 → 用户确认 → 写入 .tex → 编译验证。

---

## 前置条件

- 项目已通过 `/diss-init` 初始化，CLAUDE.md 中有完整章节结构与字数分配表
- chapters/ 下 .tex 文件已创建，含三级标题骨架和写作指引注释
- 源英文论文路径已记录在项目 CLAUDE.md 中
- 中文学术写作 agent 存在：`~/.claude/agents/sci-writer-zh.md`
- `chapters/ch*_outline.md` 已由 `/diss-outline` 生成（主入口，必需）
- `chapters/ch*_material.md` 已由 `/diss-outline` 步骤 2.5 生成（新增/展开节的文献素材来源，可选）

---

## 四种写作模式

每个 subsection 在 `/diss-init` 阶段已标注内容来源，对应四种写作模式：

| 模式 | 标注 | 说明 | sci-writer-zh 指令重点 |
|:-----|:-----|:-----|:----------------------|
| **改写** | `改写（源 section: X.X）` | 英文内容用中文学术逻辑重写，**不是翻译** | 重构段落结构，按中文论文行文习惯组织；补充中文语境下的背景解释 |
| **展开** | `展开（源 section: X.X）` | 英文简要提及的内容大幅展开 | 补充方法原理推导、背景数据、技术细节、文献引用等英文论文省略的内容 |
| **新增** | `新增` | 英文论文没有的内容 | 绪论背景、对策建议等中国学位论文特有章节，需独立构思 |
| **重组** | `重组（源 section: X.X, Y.Y）` | 多个英文 section 内容整合 | 将分散的内容按中文章节逻辑重新组织，确保融为一体而非拼接 |

---

## 参数解析

从 `$ARGUMENTS` 识别目标：

- `chapter=N`：指定要撰写的章节编号（如 `chapter=3`）
- `section=X.Y`：指定章节内某一节（如 `section=3.2`）
- 无参数：读取 CLAUDE.md 中的撰写进度，自动定位下一个待撰写章节

## 执行步骤

### Step 0：前置准备

#### 0.0 阶段转换检查

读取 CLAUDE.md `## 项目阶段`，如当前阶段为 `literature`，更新为 `drafting`（与 /diss-outline 的转换逻辑保持一致——两个入口都可触发此转换）。

#### 0.1 读取项目上下文

```
读取项目 CLAUDE.md → 获取：
  - 章节结构与字数分配表（含每节的内容来源标注）
  - 源项目路径（CLAUDE.md「`源项目路径`」字段，即源英文论文项目的绝对路径）
  - 撰写进度（哪些章节已完成）
  - 术语表（如有）
  - 学位类型（硕士/本科）
```

#### 0.1.5 写作模式解析（硬约束）

从 `ch{N}_outline.md` 或 `chapters/ch{N}.tex` 注释中为每个 subsection 解析"内容来源"标注，确定其写作模式（改写 / 展开 / 新增 / 重组）：

**精确正则**（必须匹配其一，不可模糊推断）：
```
^(\*\*)?(?:内容来源|来源)(\*\*)?[：:]\s*(?P<mode>改写|展开|新增|重组)(?:（[^）]*）)?\s*$
```
- 支持 `**内容来源**：改写（源 section: 3.2）` 或 `内容来源: 展开` 等格式
- 括号内（如 `源 section: X.X`）可选，但 `mode` 必须精确为四个汉字之一

**解析策略**：
1. 对每个 subsection，先尝试从 `ch{N}_outline.md` 的对应小节正则匹配
2. outline 无命中 → 回退到 `chapters/ch{N}.tex` 的 `% 内容来源：...` 注释行正则匹配
3. **两处都无命中或格式不符 → 阻断**，列出缺失节并 AskUserQuestion 让用户澄清；**严禁让 LLM 模糊推断**（否则 sci-writer-zh 收到的 `{MODE}` 错乱，导致素材注入 / 写作风格系统性偏差）

解析结果绑定到该 subsection 的 `MODE` 变量，在 Step 1.1 素材注入和 Step 1.2 prompt 构造中使用。

#### 0.2 读取源英文论文

```
读取源项目 manuscript.tex → 获取：
  - 全文内容（按 section 索引）
  - 图表定义与引用
  - 参考文献 bib 文件
```

#### 0.3 读取章节大纲与素材

读取 `chapters/ch{N}_outline.md`（N = 目标章节号），提取：写作要点、参考段落、术语对照、写作注意、图表需求。**不存在 → 停止并提示"请先跑 `/diss-outline` 生成章节大纲"。**

读取 `chapters/ch{N}_material.md`，按 subsection 标题索引素材包（每个 `##` 标题对应一个 subsection 的素材）：
- **header 匹配校验**：material.md 的 `##` 标题必须与 outline.md 的 `###` 标题（或 .tex 的 `\subsection`）一致。如有不匹配，在对话中 WARNING 列出差异条目
- **citation key 校验**：扫描 material.md 中所有 `**citation_key**` 引用，检查是否存在于项目 bib 文件中。不存在 → WARNING 列出缺失 key
- **不存在** → 跳过素材注入（改写模式只需 outline 即可工作）

#### 0.4 确定目标章节

- 如用户指定 `chapter=N`：定位到第 N 章
- 如用户指定 `section=X.Y`：定位到具体小节
- 如未指定：从 CLAUDE.md 进度表中找到第一个状态为 `pending` 或 `outlined`（尚未 `drafted`）的章节，向用户确认

向用户展示待撰写章节的骨架信息：
```
📖 准备撰写：第X章 {章节标题}
   - 目标字数：{total} 字
   - 包含 {N} 个小节
   - 内容来源分布：改写 M 节 / 展开 N 节 / 新增 P 节 / 重组 Q 节
   确认开始？
```

等待用户确认。

### Step 1：逐节撰写（核心循环）

**每次处理一个 section（二级标题），section 内按 subsection（三级标题）顺序串行推进。**

串行原因：中文学位论文各节之间有强逻辑依赖（前文定义的术语、概念、数据在后文引用），并行会导致术语不统一和上下文断裂。

```
SET {PRIOR_OUTPUTS} = ""    // 本章已完成的前序内容

FOR EACH section IN chapter.sections (SEQUENTIAL):
  FOR EACH subsection IN section.subsections (SEQUENTIAL):
    a. 准备素材（Step 1.1）
    b. 调用 sci-writer-zh（Step 1.2）
    c. 用户审阅确认（Step 1.3）
    d. 写入 .tex（Step 1.4）
    e. 更新 {PRIOR_OUTPUTS}
  END FOR
END FOR
```

#### Step 1.1 — 准备素材

根据当前 subsection 的内容来源标注，组装 sci-writer-zh 的输入：

**主入口：`ch*_outline.md`**

以 outline 中对应 subsection 的大纲为主入口：
- 直接使用其**写作要点**作为写作蓝图
- 直接使用其**参考段落**（已含 manuscript.tex 原文引用和行号）
- 直接使用其**术语对照**
- 直接使用其**写作注意**
- 仅在 outline 信息不足时（如参考段落为空），才回源 manuscript.tex 补充

**素材注入（当前节为新增/展开模式且 `ch*_material.md` 存在时）**：

从 material.md 读取当前 subsection 对应的素材包（按 `##` 标题匹配）：
- 提取「应引用文献」列表（含 citation_key + 核心论点 + 本节用法 + **[分级: 核心/重要/备选] 标签**）
- **分级标签保留**：material.md 中每篇文献素材的 `[分级: ...]` 标签必须原样保留进入 prompt，不可丢弃
- 提取「源项目可复用素材」（如有）
- 提取「外部数据需求」或「需要补充的内容」（如有）
- 注入 sci-writer-zh prompt 的「## 参考文献素材」字段，按 核心→重要→备选 排列

**图表就绪检查**：
- 获取当前节需要的图表列表（来自 outline 图表需求）
- 未创建 → 提醒用户先用 `/figure` 或 `/latex-table` 创建

**每节通用注入**：
- {PRIOR_OUTPUTS}：本章前序已完成内容
- 项目术语表（从 CLAUDE.md `## 术语表` 读取）
- 字数目标
- 从项目 bib 文件中提取当前节可能用到的引用条目（供 prompt 的「可用引用」字段）。提取策略：outline 的写作要点/参考段落中出现的 `\cite{}` key + material.md 中列出的 citation_key

#### Step 1.2 — 调用 sci-writer-zh

调用 `~/.claude/agents/sci-writer-zh.md`（`subagent_type: "sci-writer-zh"`），prompt 要素：

```
你正在为一篇中国{硕士/本科}学位论文撰写 **{Section Title}** 部分。

## 写作模式：{改写/展开/新增/重组}

## 目标字数：{WORD_TARGET} 字（允许 ±15% 浮动）

## 章节位置
- 所在章：第{N}章 {章节标题}
- 前一节：{prev_section_title}（已完成）
- 后一节：{next_section_title}（待撰写）
- 在全文中的角色：{基于位置推断}

## 源英文内容
{SOURCE_CONTENT — 改写/展开/重组模式提供；新增模式标注"无源内容"}

## 写作指引
注入 ch*_outline.md 中对应 subsection 的完整结构化大纲（写作要点 + 参考段落 + 术语对照 + 写作注意）

## 本章前序内容（保持术语和行文一致）
{PRIOR_OUTPUTS}

## 术语表约束
{TERMINOLOGY — 如有}

## 可用引用
{CITATIONS — 从 bib 文件提取的相关条目}

## 参考文献素材（仅新增/展开模式且 material.md 存在时提供）
以下是本节应引用的文献及其核心论点。请将这些论点有机地编织到正文叙述中，
不要简单罗列"XX研究了YY"，而要将其作为论证链条的一环。

{MATERIAL_CONTENT — 从 ch*_material.md 提取当前 subsection 对应的素材包，每篇文献保留 `[分级: 核心/重要/备选]` 标签}

**分级优先级（硬约束，适用所有模式）**：
- 每篇文献素材都带 `[分级]` 标签（来自 lit-pool 的 tier）：核心 > 重要 > 备选
- 引用优先顺序：**核心必引 > 重要应引 > 备选可选**
- 改写/展开模式下：原英文论文已引用的文献保持引用；新增的辅助文献按此优先级从素材包补充
- 新增模式下：核心/重要文献必须覆盖，备选文献选择性引用
- 重组模式下：多段源内容融合时，优先保留核心引用，避免删除高分级文献

每篇文献的「本节用法」说明了引用方式（注意：下方"作者名\cite{key}"表示必须显式写出作者姓名 + 引用命令，因为顺序编码制下 \cite{} 仅渲染为 [N]）：
- "定义概念" → 如"Barney\cite{barney1991f}将YY定义为……"
- "支撑论点" → 如"这一观点得到了作者名\cite{key}的支持……"
- "提供证据" → 如"作者名\cite{key}基于YY数据发现……"
- "对比讨论" → 如"与作者名\cite{key}的研究不同，本文……"

{如 material.md 不存在或当前节为改写/重组模式，省略"新节素材"但仍注入分级优先级说明}

## 中文学术写作要求
1. 使用正式学术中文，避免口语化和翻译腔
2. 段落结构：总-分-总，每段一个中心论点
3. 句式：长短句搭配，避免全部使用"…的…的…的…"嵌套定语
4. 过渡：段落间使用逻辑连接词自然过渡
5. 引用格式（GB/T 7714-2015 顺序编码制）：
   - **句末/括注引用**（文献不是句子主语）：使用 `\cite{key}`，如"……研究表明\cite{key}。"
   - **作者主语引用**（作者名是句子的语法主语）：**必须显式写出作者名** + `\cite{key}`，如"Barney\cite{barney1991f}指出……"或"张三等\cite{zhang2023s}认为……"。禁止单独用 `\cite{key}` 充当句子主语——顺序编码制下 `\cite{}` 仅渲染为 [N]，作者信息会丢失
6. 图表引用：仅放置 \ref{} 引用，不创建图表本身
7. 数字规范：正文中十以内用汉字，十以上用阿拉伯数字；数据/公式中一律用阿拉伯数字
8. 标点：全部使用中文全角标点

## 模式专属指令

### 改写模式
- 禁止逐句翻译，必须按中文论文的论证习惯重新组织段落
- 英文论文假设读者有领域背景，学位论文需要更多上下文铺垫
- 可以调整论证顺序，增加过渡段落

### 展开模式
- 英文论文中一句带过的内容，在学位论文中可能需要 200-500 字展开
- 补充方法原理、技术背景、数据来源说明等
- 保持与英文论文结论一致，但论证过程需要更详细
- 如提供了「参考文献素材」，优先使用素材中的文献来补充英文论文未涵盖的细节（而非重复英文原文已引用的文献）

### 新增模式
- 完全独立写作，参考写作指引和参考文献素材
- 绪论背景需引用权威数据和政策文件
- 对策建议需具体、可操作，避免空泛
- 如提供了「参考文献素材」，必须在正文中引用其中的核心/重要文献，备选文献可选择性引用

### 重组模式
- 将多段源内容融为一体，不是简单拼接
- 统一术语、统一视角、重写过渡段
- 确保读者感受到的是连贯叙述而非拼接痕迹
- 不注入参考文献素材（重组的核心是整合已有英文源内容，不引入新文献）

## 输出
1. 完整的 LaTeX 内容（```latex``` 代码块）
2. 实际字数统计
3. 使用的引用 key 列表
4. 内容覆盖度自检：源内容的哪些要点已覆盖，哪些被省略（附理由）
```

#### Step 1.3 — 用户审阅

向用户展示 sci-writer-zh 的产出：

```
## {Section X.Y.Z Title} — 初稿

> 写作模式：{改写/展开/新增/重组} | 目标：{target}字 | 实际：{actual}字

{LaTeX 内容预览（渲染关键段落的纯文本摘要，不超过 500 字）}

---
📊 字数：{actual} / {target}（{percentage}%）
📚 引用：{N} 个 citation key
📋 覆盖度：源内容 {X}/{Y} 个要点已覆盖

选项：
  [1] 确认写入 ✓
  [2] 修改后写入（请指出需要修改的地方）
  [3] 重新生成（请说明不满意之处）
  [4] 跳过此节，稍后处理
```

**等待用户明确选择后才继续。**

- 选 [2]：根据用户反馈修改（主 agent 直接修改或重新调用 sci-writer-zh）
- 选 [3]：重新调用 sci-writer-zh，将用户反馈作为额外指令
- 选 [4]：在 .tex 对应 `\subsection{}` 下插入一行 `% TODO: 本节正文稍后补写` 注释，章节级状态保持为 `outlined`（不引入 `skipped` 状态——全局状态机只有 `pending → outlined → drafted → polished`），继续下一节。diss-finalize Phase 0.4 会对 `outlined` 章节报警，此时再决定补写或删节。

#### Step 1.4 — 写入 .tex 文件

用户确认后，将 LaTeX 内容写入对应 chapter .tex 文件：

1. 读取当前 .tex 文件
2. 定位到目标 subsection 的位置（在骨架注释之后）
3. 替换骨架注释为实际内容（保留 `\subsection{}` 标题）
4. 删除骨架注释行（`% 目标字数：` `% 内容来源：` `% Guidelines:` `% 写作要点：` `% 详细大纲见`）——diss-outline Step 2.2 追加的五类注释全部在此清理
5. 写入文件
6. Git Checkpoint：
   > Checkpoint 卡：列出本步精确文件（建议提交信息 `diss-draft: write §{X.Y.Z} {subsection_title}`），经 AskUserQuestion 单独确认后再执行 focused staging/commit；默认不 push（规格 §5）。

### Step 2：本章小结

每章最后一节固定为「本章小结」。在该章所有其他节完成后：

1. 汇总本章所有已写内容的核心要点
2. 调用 sci-writer-zh 生成本章小结（200-300 字）
3. prompt 额外指令：
   ```
   本章小结要求：
   - 概括本章的主要工作和结论（不引入新内容）
   - 按本章的节结构顺序逐点总结
   - 自然过渡到下一章（如有）
   - 字数：200-300 字
   - 不需要引用文献
   - 过渡到下一章时，参考 ch*_outline.md 中下一章的章节概览（标题和主要内容），不依赖下一章的正文内容
   - 如果是最后一章（结论章），不需要过渡句
   ```
4. 用户确认后写入

### Step 3：编译验证

本章全部节写入完成后：

1. 运行 `latexmk` 编译
2. 检查编译输出：
   - **编译失败** → 分析错误日志，修复 LaTeX 语法（常见：未转义特殊字符、引用 key 不存在、环境未关闭）
   - **编译成功但有关键 warning** → 报告：
     - `Citation undefined` → 标记待补引用，列出缺失 key
     - `Reference undefined` → 检查 `\ref` 对应 `\label`，修复
     - `Float specifier changed` → 建议调整浮动体参数
   - **编译成功无关键 warning** → 报告 PDF 页数，继续
3. 修复后重新编译，直到通过或仅剩非关键 warning

### Step 4：更新进度

更新 CLAUDE.md `## 撰写进度` 中该章节状态为 `drafted`。

在项目 CLAUDE.md 中更新撰写进度：

```markdown
## 撰写进度
- [x] 第1章 绪论 — drafted (2026-xx-xx)
  - [x] 1.1 研究背景 (1,150字)
  - [x] 1.2 研究目的及意义 (820字)
  - [x] 1.3 研究范围及内容 (710字)
  - [x] 1.4 研究方法与技术路线图 (680字)
  - [x] 1.5 本章小结 (230字)
  - 本章合计：3,590字 / 目标3,500字
- [ ] 第2章 文献综述及理论基础 — pending
- [ ] ...
```

### Git Checkpoint（里程碑：第 N 章初稿完成）

> Checkpoint 卡：列出本步精确文件（建议提交信息 `diss-draft: ch{N} complete ({actual}字)`），经 AskUserQuestion 单独确认后再执行 focused staging/commit；默认不 push（规格 §5）。

## 核心原则

1. **扩写不是翻译**：禁止逐句翻译英文论文。中文学位论文有自己的论证结构和行文逻辑，必须按中文学术规范重新组织
2. **交互确认制**：每一节写完必须用户确认后才写入 .tex，绝不自动写入
3. **串行推进**：同一章内严格按节顺序串行，保证术语和上下文一致性
4. **每章一编译**：每章写完必须编译验证，不积累错误
5. **字数约束**：每节字数控制在目标 ±15% 以内；如偏差过大，提醒用户并建议调整
6. **图表只引不建**：正文中使用 `\ref{fig:xxx}` 和 `\ref{tab:xxx}` 引用图表，不在 diss-draft 中创建图表内容（图表由单独流程处理）
7. **引用规范**：GB/T 7714-2015 顺序编码制。句末引用用 `\cite{key}`（渲染为 [N]）；作者作为主语时必须显式写出作者名 + `\cite{key}`（如"Barney\cite{barney1991f}指出"）。引用 key 必须在 bib 文件中存在；如需新增引用，标记 `(ref)` 待后续补充
8. **保持与源论文结论一致**：扩写可以增加论证细节和背景，但不能改变研究结论和核心发现

## 特殊章节处理

### 绪论（第1章）

- 全部为「新增」或「改写」模式
- 研究背景需引用具体行业数据（年份、数值、来源）
- 技术路线图：在 `\ref{}` 处标注待创建，提醒用户后续用 `/figure` 生成
- 1.3.2 研究内容需与实际章节结构完全对应

### 文献综述（第2章）

- 大量「展开」和「新增」
- 每个研究领域的综述需形成"梳理-评述-定位"的逻辑闭环
- 研究现状述评必须明确指出 Gap，与绪论和 idea.md 呼应
- 引用密度最高的章节，注意引用格式规范

### 技术型章节（第3-5章）

- 以「改写」和「展开」为主
- 方法原理部分需要大幅展开（英文论文假设读者懂，学位论文不假设）
- 公式推导需逐步展示，不跳步
- 数据描述需更详细（样本来源、采集过程、预处理步骤）

### 对策建议章

- 全部为「新增」
- 建议必须从研究结论出发，不能凭空提出
- 每条建议需具体、可操作，避免"应当加强""需要提高"等空泛表述
- 按维度/层面分类，形成体系

### 结论章

- 主要为「改写」
- 研究结论按 RQ 逐条总结，与前文各章结论保持一致
- 创新点 3-4 条，措辞需谦虚但明确
- 研究不足与展望需诚恳，不回避真实局限

## 术语管理

术语表唯一正本：**项目 CLAUDE.md 的 `## 术语表` section**。

- **读取**：每章撰写前从 CLAUDE.md 读取（应在 /diss-outline 阶段已建立）
- **创建**（仅当术语表不存在——即跳过了 outline 阶段）：首节完成后提取关键术语，用户确认后写入 CLAUDE.md
- **追加**：新术语出现时追加到 CLAUDE.md 术语表并通知用户
- **绝不重建**：已有术语表时只追加，不重新创建
