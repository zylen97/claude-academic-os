# Fund Draft — 基金申请书逐节撰写

**规格**：`~/.claude/skills/shared/FUND-PROTOCOL.md`（下称"协议"）。

基于 `/fund-outline` 生成的大纲，逐节撰写基金申请书的中文正文。核心要求：**说服性学术写作**——不是描述已完成的研究，而是论证为什么这个研究值得资助。

**与论文写作的关键区别**：
- **说服性**：每段都在回答"为什么值得资助"，不是"我做了什么"
- **前瞻性**：研究方案用将来时，描述"将要做什么"而非"做了什么"
- **综合性**：多个源项目的内容需要编织成一条叙事主线
- **简洁有力**：基金评审时间有限，每句话都必须有信息增量

**输入** `$ARGUMENTS`：`section=XXX`（可选，不指定则交互式选择）。

## 步骤 0：前置准备

### 0.0 阶段检查

FUND.md 阶段为 `outlining` → 改为 `drafting`。阶段为 `init` 或 `literature` → 提示先运行 `/fund-outline`；只写"表格"角色的章节时可以继续，阶段不改。其他阶段不改。

### 0.1 解析 `$ARGUMENTS`

- 提取 `section` 参数（章节编号 `{NN}` 或章节名）
- 无 `section` → 列出 CLAUDE.md 章节规划表里状态不是"定稿"的章节，AskUserQuestion 询问要写哪个

### 0.2 读取项目配置

- `FUND.md`：申请人代码 `{代码}`、档案、前序申请
- `CLAUDE.md`：交付类型、合规要点、源项目、`## 章节规划`（文件、角色、字数上限、状态）
- `_profiles/{档案}`：匿名要求、正文结构原文、评审要点、选题定位
- 重申项目：`reviews/重申修改清单.md`

### 0.3 读取大纲文件

- 读取对应章节的 `sections/{NN}_{章节名}_outline.md` 和 `sections/synthesis_summary.md`
- 角色为 `表格` 的章节没有大纲：按官方模板栏目直接起草，内容从 fund-idea.md 和研究方案推断（如经费类目要与研究方案匹配）
- 其他章节缺大纲 → 提示先运行 `/fund-outline section={NN}`

### 0.4 读取源材料

```
FOR EACH 源项目 IN CLAUDE.md 源项目表:
  a. {源项目}/structure/0_global/idea.md
  b. {源项目}/manuscript.tex（按需读相关章节）
  c. 引用池（如有）
END FOR
```

- 本项目 `structure/2_literature/` 的引用池优先。
- **研究基础**角色的内容只从 `$FUNDINGS/_assets/{代码}/成果清单.md` 和 `申请人信息卡.md` 取。不得写入清单里没有的成果，也不得写入其他申请人的成果（协议第 2 节）。

### 0.5 进度检查

读 CLAUDE.md 章节规划表的"状态"列：
- 状态为"初稿"或"定稿" → 询问是基于现有正文修改还是重写
- 章节文件正文区已有内容（如重申继承来的正文）→ 默认在其基础上修改，并落实修改清单里涉及本章的条目

## 步骤 1：按角色路由

从 CLAUDE.md 章节规划表读本章的角色和字数上限。**传给写作 agent 的字数目标一律取规划表的值。**一个章节有多个角色时，按子节分别路由。

| 角色 | 写作模式 | 核心策略 |
|:-----|:---------|:---------|
| 立项依据 | 综合提炼 | 从多个源项目综合背景与现状，铺"已知 → 未知 → 本项目填补"的逻辑链 |
| 目标内容 | 前瞻规划 | 总目标 + 分解目标；已有成果改写为"计划研究" |
| 研究方案 | 前瞻规划 | 方法细节的前瞻表述 + 技术路线 |
| 创新点 | 成果包装 | 精炼、锐利，对标现有研究 |
| 可行性 | 成果包装 | 理论、技术、团队三方面论据 |
| 研究基础 | 成果包装 | 只用成果清单里的条目，按与本项目相关性排序 |
| 预期成果 | 前瞻规划 | 可考核的成果形式与数量、去向 |
| 进度安排 | 前瞻规划 | 按档案规定的周期和粒度分段 |
| 表格 | 模板填写 | 主 agent 按官方栏目直接填写，不调用写作 agent |

## 步骤 2：写作执行

### 2.1 写作模式定义

**模式 A：综合提炼**（立项依据）

主要用于将多个源项目的文献综述、研究背景综合为一篇连贯的立项依据。

写作指令要点：
```
- 语体：中文学术申请书体，严谨但不晦涩，有说服力
- 逻辑结构：问题引入 → 现状梳理 → 不足揭示 → 本项目切入
- 引用：用 `\cite{key}`，key 从本项目引用池或源项目 bib 中选取（与下方输出要求一致）
- 段落策略：每段一个论点，段首句是论点句
- 禁止：口语化、过度自夸、空泛表述（如"具有重要意义"不加具体说明）
- 字数严格控制在目标范围内
```

**模式 B：前瞻规划**（研究内容、研究方案）

将源项目中已有的方法/结果改写为"计划研究"的前瞻性表述。

写作指令要点：
```
- 时态转换：已完成 → 将要做（"本项目拟采用…" "将构建…" "计划通过…"）
- 保留方法核心细节，但调整为计划语气
- 突出方法的创新性和必要性（为什么用这个方法而不是别的）
- 研究内容之间的衔接要自然，体现递进关系
- 技术路线需清晰可执行，评审能一眼看懂步骤
- 可行性论证要有理有据（前期基础 / 数据可得性 / 方法成熟度）
```

**模式 C：成果包装**（创新点、研究基础）

将已有成果重新包装为基金语言。

写作指令要点：
```
- 创新点：每条一句核心 + 2-3句展开，对标现有方法的优势
- 创新点排序：理论创新 > 方法创新 > 应用创新
- 前期工作：已发表论文按与本项目的相关性排序
- 用具体成果说话（模型名、方法名、发表期刊）
- 避免空泛的自我评价，用事实论证团队能力
```

### 2.2 逐子节写作

对当前章节的每个子节：

1. **提取大纲要点**：从 `*_outline.md` 读取该子节的结构化要点
2. **提取源材料**：根据要点中的来源标注，从对应源项目读取相关段落
3. **调用 sci-writer-zh agent**：

```
使用 Agent 工具调用 sci-writer-zh agent：
- subagent_type: "sci-writer-zh"
- model: opus
- （不传 isolation 参数——全局红线）

prompt 结构（**所有硬约束字段必须注入**，不可省略）：

## 角色
基金申请书写作专家（不是论文作者，也不是学位论文作者）

## 文本类型硬约束
- 文本类型：中文基金申请书（{基金全称} — 从 FUND.md 读取）
- 与论文/学位论文的区别：**论证"为什么值得资助"，不是描述"已做了什么"**

## 评审视角
目标读者是见过数百份申请书的资深评审专家。预期阅读模式：
- 评审人**快速浏览**，关键信息必须在段首/段末
- 不耐烦读模糊表述、冗余铺垫、空洞论断
- 会**主动寻找**"创新点是否锐利""可行性是否可信""申请人是否匹配"

## 说服性要求（硬约束）
- 每一段落必须回答"为什么值得资助/为什么这样做"，不能只是描述性陈述
- 立项依据段落必须构建"已知 → 未知 → 本项目填补"的逻辑链
- 创新点用锐利陈述句：禁止"一定程度上""有所""有所创新""具有较好的"等弱化词
- 方法方案要给"这个人真的能做出来"的信心

## 时态约束
- 未完成的工作（研究内容、研究方案、预期成果）→ 将来时（"将构建""拟研究""预期得到"）
- 已有成果（研究基础、前期积累、已发表工作）→ 过去时/现在完成时
- 禁止时态混用：模式 B（展开）模式 C（新增）默认将来时

## 写作模式（与本 skill 步骤 2.1 的 A/B/C 定义对齐）
- **模式 A（综合提炼）**：将多个源项目的综述/背景综合为连贯立项依据。结构：问题引入 → 现状梳理 → 不足揭示 → 本项目切入
- **模式 B（前瞻规划）**：将源项目已有方法/结果改写为"计划研究"的前瞻性表述。时态：已完成 → 将要做（"本项目拟采用…""将构建…"）
- **模式 C（成果包装）**：将已有成果重新包装为基金语言。创新点每条一句核心 + 2-3句展开，对标现有方法优势；前期工作按相关性排序
- **模式 D（模板填写，仅"表格"角色）**：不走 sci-writer-zh，由主 agent 按官方栏目直接填写

## 基金专属要求（从档案注入，不要凭印象写）
- 选题定位：{档案"选题定位"，如"教育科学研究，须落在教育问题上"}
- 评审要点：{档案"评审要点"原文}
- 篇幅：{本章字数上限；档案对全文还有页数、图片数限制时一并写出}

## 匿名约束（档案要求匿名的章节必须注入；不要求时删去本节）
- 不得出现申请人姓名、单位、学校、所在地区，以及能指向申请人的团队成员姓名：{从 `_assets/{代码}/申请人信息卡.md` 取姓名、单位、通讯地址，列成禁用词}
- 确需提及时按档案规定替代（如"××学校""××地区""×××"）
- 前期成果按档案允许的信息写（如只写成果名称、形式、作者位次、是否核心期刊）

## 输入材料
- 综合摘要：{SYNTHESIS_SUMMARY}
- 当前子节大纲：{子节要点}
- 源材料：{从源项目提取的相关内容}
- 上下文：{已完成的前序子节文本，保持连贯；不重复论述}
- 字数目标：{子节字数}（从 CLAUDE.md `## 章节规划` 读取；严格不超，少 5% 以内可接受）
- 研究基础素材：{仅研究基础角色传入：成果清单中选定条目的原文}
- 修改清单：{仅重申项目传入：涉及本章的条目}

## 输出要求
- 纯中文学术文本，不带 markdown 标题
- 段落间用空行分隔
- 引用用 `\cite{key}` 格式（不用脚注）
- 结尾附"字数统计"和"模式自检"（是否违反说服性/时态/字数）
```

4. **展示给用户**：显示生成的文本 + 字数统计 + 来源标注
5. **用户确认**：AskUserQuestion

   - 给出修改意见 → 重新生成或手动调整

## 步骤 3：后处理

### 3.1 拼接章节文本

将所有确认的子节文本拼接为完整章节：

```
# {章节标题}

{子节1文本}

{子节2文本}

...
```

### 3.2 一致性检查

检查完整章节的：
- **术语一致性**：同一概念在不同子节中的表述是否统一
- **逻辑连贯性**：子节之间的过渡是否自然
- **字数达标**：总字数是否在上限内
- **引用完整性**：引用格式是否统一
- **成果归属**：研究基础里的每项成果都能在 `_assets/{代码}/成果清单.md` 找到
- **匿名**（档案要求时）：全文搜索禁用词（申请人姓名、单位、学校、地区），命中即列出位置

如有问题 → 指出并提供修改建议，等用户确认后修改。

### 3.3 保存

写入本章 `sections/{NN}_{章节名}.md` 的正文区（`<!-- 正文从此开始 -->` 之后），保留文件头的角色和字数注释。大纲文件保留不动。

### 3.4 更新状态

把 CLAUDE.md 章节规划表里本章状态改为 `初稿`。重申项目同时把 `reviews/重申修改清单.md` 里本章已落实条目的状态改为"已改"。

显示：
- 本章字数（实际 / 上限）、源材料利用情况
- 章节规划表里各章状态

  - 还有未写章节 → `/fund-draft section={NN}`
  - 全部为初稿 → `/fund-polish`（润色、提交前自检、生成交付稿）
