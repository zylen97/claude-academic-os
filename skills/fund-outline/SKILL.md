# /fund-outline — 基金申请书大纲

**规格**：`~/.claude/skills/shared/FUND-PROTOCOL.md`（下称"协议"）。

从 2–3 个已有研究项目中**综合提炼**，为各章生成结构化大纲。核心难点是把几个独立研究编织成一个逻辑自洽、前后呼应的研究计划。

**输入** `$ARGUMENTS`：可选 `section={NN}`，只做某一章；不指定则按章节规划顺序全做。

## 步骤 0：前置准备

### 0.1 读项目配置

- `FUND.md`：申请人代码、档案、阶段、前序申请
- `CLAUDE.md`：交付类型、合规要点、源项目、`## 章节规划` 表（章节、文件、角色、字数上限、状态）
- `_profiles/{档案}`：正文结构原文、评审要点、选题定位
- `fund-idea.md`
- 重申项目：`reviews/重申修改清单.md`，以及各章里继承来的正文

**章节集合、顺序和字数以 CLAUDE.md 章节规划表为准**，本 skill 不硬编码任何基金的章节。

### 0.2 阶段

FUND.md 阶段为 `init` 或 `literature` → 改为 `outlining`。其他阶段不改。

### 0.3 读源项目材料

对 CLAUDE.md 源项目表里的每个项目：

```
a. {源项目}/CLAUDE.md → 项目阶段与结构
b. {源项目}/structure/0_global/idea.md → Gap、RQ、方法、贡献
c. {源项目}/manuscript.tex → 正文结构、核心论点、方法细节
d. {源项目}/structure/2_literature/（如有）→ 文献综述素材
```

本项目自己的 `structure/2_literature/`（/lit-workflow 产出的引用池）优先于源项目文献。

研究基础相关内容只从 `$FUNDINGS/_assets/{代码}/成果清单.md` 取（协议第 2 节）。

### 0.4 综合摘要

基于以上材料写 `{SYNTHESIS_SUMMARY}`，回答：

1. **统一主线**：这几个项目之间的内在关联
2. **递进关系**：如何构成递进、互补或系统的研究计划
3. **共同 Gap**：共同指向的更大空白
4. **总目标**：超越单个项目，整个计划要回答的核心问题

重申项目另加第 5 条：**本轮相对前序的主要改动**（来自修改清单）。

展示给用户，确认或修改后保存为 `sections/synthesis_summary.md`。

## 步骤 1：逐章生成大纲

按章节规划表顺序处理每一章。角色为 `表格` 的章节跳过（见步骤 2）。一个章节有多个角色时（如 `目标内容+创新点`），按下列对应写法依次生成，合并在同一个大纲文件里。

每章大纲写入 `sections/{NN}_{章节名}_outline.md`（文件名 = 章节文件名加 `_outline`）。字数目标取规划表的字数上限，并在大纲里给出各子节的字数分配。

各角色的写法：

### 角色：立项依据

- **背景与意义**：实践背景（各源项目 motivation 综合）、理论背景、理论意义与实践价值（比单篇论文更宏观；档案有选题定位要求时，意义要扣住定位）
- **研究现状**：按主题分 3–5 个方向，每个方向给代表性成果（标 citation key）、趋势、不足
- **述评**：现有研究的整体不足，每条不足要能对应后面的一项研究内容
- **关键科学问题**：2–3 个，展示"现状不足 → 科学问题 → 本项目切入点"

### 角色：目标内容

- **总目标**：一段话
- **研究内容**：每项写研究对象、方法、预期产出；内容之间必须有递进或支撑关系，给出内容关联图的文字描述
- **关键问题 / 重点难点**：每个对应至少一项研究内容

### 角色：研究方案

- **技术路线**：按研究内容顺序组织，标各步骤的输入输出（后续可用 `/figure` 画路线图）
- **各内容的具体方案**：理论基础、模型或分析框架、数据来源、方法步骤（从源项目方法部分改写为前瞻表述）、预期结果

### 角色：创新点

3–4 条：理论创新至少 1 条、方法创新至少 1 条、应用创新可选。每条一句概括 + 对标现有研究的优势 + 来源项目。每条都要能在"立项依据"的述评里找到对应的不足。

### 角色：可行性

理论可行性、技术与方法可行性（数据可得性、方法成熟度）、团队与条件可行性。每个维度 2–4 条具体论据，标出哪些已落地、哪些需补充。

### 角色：研究基础

- 前期成果：从成果清单选与本项目最相关的条目（写条目编号），说明每项与哪项研究内容对应；档案限填项数时按限额选
- 已有数据、模型、代码、合作资源
- 申请人背景与团队分工
- 档案要求匿名的章节：大纲里注明"成果只写名称、形式、作者位次等档案允许的信息"

### 角色：预期成果

成果形式与数量（论文、报告、专著等，可考核）、成果去向；档案要求分中期、结项或分负责人与成员列出时照档案结构写。数量要和研究内容、周期匹配，不要虚高。

### 角色：进度安排

按档案的研究周期和计划粒度（年度、半年度）分段，每段写任务和阶段性成果，覆盖所有研究内容，避免前松后紧。

### 重申项目

每章大纲末尾加一节"本章落实的修改"，列出修改清单里涉及本章的条目编号和具体改法。全部章节做完后，检查修改清单里每一条都至少被一章落实；没有落实的列出来请用户决定。

### 每章确认

展示该章大纲（标注每个要点的来源项目、哪些是直接复用、哪些是综合升华、字数分配），AskUserQuestion 确认或修改，再写文件。写完把 CLAUDE.md 章节规划表里该章状态改为 `大纲`。

## 步骤 2：表格类章节

角色为 `表格` 的章节不产大纲。提示用户按官方模板直接填写对应的 `sections/{NN}_{章节名}.md`（经费类目、基本信息栏目以档案和官方模板为准）。/fund-draft 对这类章节有"无大纲"分支。

## 步骤 3：汇总

显示：
- 各章大纲完成状态、各章字数分配与总字数（对照档案总字数或页数上限）
- 源项目素材利用情况（复用了什么、哪些要新写）
- 主线逻辑：立项依据的不足 → 研究内容 → 创新点 → 预期成果的对应关系
- 重申项目：修改清单落实情况

提示：运行 `/fund-draft` 逐章撰写正文。

## 注意事项

- 本 skill 只负责 `init/literature → outlining` 的转换；`outlining → drafting` 由 /fund-draft 入场时写。
- 不修改源项目的任何文件。
