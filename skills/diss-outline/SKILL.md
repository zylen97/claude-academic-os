# Diss-Outline — 学位论文逐章扩写大纲

读取源英文论文（manuscript.tex + idea.md）和 diss-init 创建的章节骨架，**逐章交互式**生成详细的写作大纲。产出的大纲为 `/diss-draft` 提供无歧义的写作输入。

**本 skill 不写正文**，只产出结构化的写作要点和内容映射。

## 参数解析

从 `$ARGUMENTS` 识别目标项目或章节。

- 如果在 `dissertations/` 某个子目录下运行：自动检测当前项目
- 如果提供了学生姓名（如 `车茜`）：在 `dissertations/` 下查找匹配的文件夹
- 如果提供了章节号（如 `ch3`、`第三章`）：只处理该章
- 否则：列出 `dissertations/` 下所有项目，用 AskUserQuestion 让用户选择

## 步骤 0：前置准备

### 0.1 读取项目 CLAUDE.md

从项目 CLAUDE.md 提取：
- `源项目路径`（指向 Zylen paper 或 _gym paper 下的英文论文项目）
- `学位论文章节结构`（diss-init 生成的完整三级标题 + 字数分配表）
- `学位类型`（硕士/本科）
- `项目阶段`

### 0.2 读取源英文论文

从源项目读取：
- `manuscript.tex`：完整英文正文（提取每个 section/subsection 的文本内容）
- `idea.md`：RQ、Gap、方法框架、核心贡献
  - **fallback**：如源项目无 idea.md（老项目非 `/paper-init` 创建），从 manuscript.tex 的 Introduction（RQ声明段落）和 Abstract 中提取 RQ、Gap、方法框架，功能等价
- 源项目 CLAUDE.md：项目概况

**构建英文论文内容索引**：
```
Section 1: Introduction → 行号范围 [L10-L85]
Section 2: Literature Review → 行号范围 [L86-L150]
  2.1 xxx → [L90-L120]
  2.2 xxx → [L121-L150]
Section 3: Methodology → 行号范围 [L151-L280]
...
```

### 0.3 读取章节骨架

读取 chapters/ 下所有 .tex 文件，提取已有的三级标题和注释（目标字数、内容来源标注）。

### 0.4 检查引用池（素材准备前置）

**citation_pool 路径解析**（按优先级）：
1. 本项目 CLAUDE.md 中定义的 citation_pool 路径（如已通过 /lit-workflow 生成）
2. 源项目路径下的 `structure/2_literature/citation_pool/`（从 CLAUDE.md 的「`源项目路径`」字段读取）
3. 都不存在 → 提示用户先运行 /lit-workflow

解析成功后，将实际路径记录为 `CITATION_POOL_PATH`（供 Step 2.5.1 和 2.5.6 引用）。

检查解析到的 citation_pool 目录是否存在且包含标签文件：
- **存在** → 标记 `CITATION_POOL_AVAILABLE = true`，记录可用标签文件列表
- **不存在** → 标记 `CITATION_POOL_AVAILABLE = false`，在对话中提示用户：
  > ⚠️ 未检测到引用池（citation_pool/），步骤 2.5 的素材准备将跳过。
  > 建议先运行 `/lit-workflow` 生成引用池，以提高新增/展开节的写作质量。
  >
  > 是否继续生成结构大纲（不含素材准备）？

### 0.5 确定处理范围

- 如果 `$ARGUMENTS` 指定了章节号 → 只处理该章
- 否则 → 向用户展示全部章节列表，询问：
  - 逐章处理（推荐，从第一章开始）
  - 指定某一章开始

---

> **逐章循环结构**：步骤 1、2、2.5 对**每一章**依次执行，然后进入下一章。步骤 3、4 在所有章节完成后才执行。
>
> ```
> FOR EACH chapter (SEQUENTIAL):
>   步骤 1: 生成结构大纲 → 用户确认
>   步骤 2: 保存 outline.md + 更新 .tex 注释 + git checkpoint
>   步骤 2.5: 素材准备 → 保存 material.md + git checkpoint
> END FOR
>
> 步骤 3: 生成总览摘要（所有章节完成后）
> 步骤 4: 更新 CLAUDE.md + 最终 git checkpoint
> ```

---

## 步骤 1：生成结构大纲（每章执行）

对每一章执行以下流程。**每章完成后必须等用户确认，才进入下一章。**

### 1.1 展示章节概览

向用户展示当前章节的：
- 章节标题与全部三级标题
- 各节目标字数（来自 diss-init）
- 各节内容来源标注（改写/展开/新增/重组）

> **字数权威源声明（B8 要求）**：本 skill 将节级字数目标写入 `ch{N}_outline.md` 的 `**目标字数**: XXX 字` 字段——**此字段是下游 /diss-draft 的唯一权威源**。`.tex` 注释中的 `% 目标字数` 会在 diss-draft 写入正文时被删除，不能作为持久源；CLAUDE.md `## 撰写进度` 表只有章级合计（非节级），也不是节级权威源。若 diss-draft 在 ch*_outline.md 找不到节级字数 → 必须阻断并提示用户先跑 /diss-outline，不可让 sci-writer-zh 自行推断字数。

### 1.2 逐节生成写作大纲

对当前章节的**每个三级标题**（`\subsection`），生成以下结构化大纲：

```markdown
### X.Y.Z 三级标题

**目标字数**：XXX 字

**内容来源**：改写（← English §3.2）/ 展开（← English §2.1，需补充原理）/ 新增 / 重组

**写作要点**（根据目标字数调整，约每 300-500 字一条）：
1. [要点1]：一句话描述这段要写什么，包含关键论证逻辑
2. [要点2]：...
3. [要点3]：...
（1000字以下 3-4 条，1000-2000字 4-6 条，2000字以上 6-10 条）

**参考段落**（仅限改写/展开类型）：
> [引用 manuscript.tex 中对应的英文原文段落，标注源 section 编号]
> — Source: §X.Y, L100-L120

**关键术语对照**（列定义与 diss-init `## 术语表`、diss-outline Step 3.3 总表一致）：
| 英文术语 | 中文译法 | 首次出现章节 | 备注 |
|---------|---------|------------|------|
| xxx     | xxx     | 本文采用的译法 / 学界通用译法 |

**写作注意**：
- [该节的特殊要求，如：需补充国内案例/需引用中文文献/需绘制示意图等]

**素材标签**（仅限新增/展开类型，改写/重组不需要；由主 agent 基于步骤 2.5.1 的 tag-to-chapter 映射表自动填写，不需要用户提供）：
{如：METHOD-基础, LR — 步骤 2.5 据此定位 citation_pool 文件}

**图表需求**（如本节无图表需求，标注"无"）：
- [ ] 图X.Y：{描述}（类型：TikZ概念图/Python数据图/R统计图）
- [ ] 表X.Y：{描述}
```

### 1.3 章节类型专属规则

不同章节类型有不同的中文学术写作惯例，生成大纲时必须遵循：

#### 第一章 绪论

- **1.1 研究背景**：必须从宏观到微观递进，新增国内行业数据和政策背景（英文论文通常没有）
- **1.2 研究目的及意义**：理论意义和实践意义必须分条列点，每条 2-3 句
- **1.3 研究范围及内容**：需包含「全文地图」——逐章概述每章做什么
- **1.4 研究方法与技术路线图**：需标注"新增：技术路线图（flowchart）"
- **1.5 本章小结**：固定格式，2-3 句概括本章内容

#### 第二章 文献综述及理论基础

- 每个综述方向需标注：概念界定 → 研究现状 → 研究不足
- **理论基础节**：需展开讲理论起源、核心观点、在本研究中的适用性（英文论文通常一笔带过）
- **研究现状述评**：必须明确指出 Gap，与 idea.md 中的 Gap 一致
- 标注哪些文献需要补充中文来源（CNKI）

#### 第三章 研究设计/模型构建

- **方法原理**必须单独成节并充分展开（英文论文假设读者懂，学位论文不能）
- 变量定义表、数据来源说明需比英文论文更详细
- 模型公式需逐步推导，不能像英文论文那样跳步

#### 核心研究章节（第四、五、六章等）

- 每章对应 1-2 个 RQ，大纲中必须标注 RQ 映射
- 结果呈现：标注需要的图表清单（表X.X、图X.X）
- 结果讨论：标注需要对比的已有研究（从 literature review 中提取）

#### 对策建议章

- 通常为**新增**内容（英文论文的 Implications 只有 1-2 段）
- 每条建议需包含：问题诊断 → 对策内容 → 实施路径
- 建议维度需与研究发现一一对应

#### 结论章

- 主要研究结论按 RQ 逐条总结
- 创新点 3-4 条，需与绪论中的研究意义呼应
- 研究不足与展望：诚实列出局限性

### 1.4 用户确认

以完整 markdown 格式展示当前章节的所有三级标题大纲，用 AskUserQuestion 请用户确认：
- 确认无修改 → 保存并进入下一章
- 需要修改 → 根据反馈调整后重新展示，再次确认

**关键术语对照**（列定义与 diss-init `## 术语表`、diss-outline Step 3.3 总表一致）：
| 英文术语 | 中文译法 | 首次出现章节 | 备注 |

### 2.2 同步更新 ch*.tex 注释

在对应 .tex 文件的每个 `\subsection` 下方，追加或更新简要注释：

```latex
\subsection{X.1.1 三级标题}

% 目标字数：XXX字
% 内容来源：改写（← English §X.X）
% 写作要点：(1) xxx (2) xxx (3) xxx
% 详细大纲见 ch1_outline.md
```

### 2.3 Git Checkpoint（结构大纲 + .tex 注释）

> Checkpoint 卡：列出本步精确文件（建议提交信息 `diss-outline: ch{N} structural outline confirmed`），经 AskUserQuestion 单独确认后再执行 focused staging/commit；默认不 push（规格 §5）。

> **注意**：material.md 在步骤 2.5 才生成，不在此处 add。素材文件的 git checkpoint 在步骤 2.5.5。

## 步骤 2.5：素材准备（每章自动执行）

每章结构大纲用户确认并保存后，**自动执行**素材准备，为新增/展开节匹配 citation_pool 文献素材。

> **职责边界**：本步骤只组装「引用谁 + 说了什么 + 怎么用」的结构化素材指引，不写任何正文。正文由 `/diss-draft` 的 sci-writer-zh 根据素材执行写作。

### 2.5.1 前置：读取 citation_pool

从步骤 0.4 解析到的 citation_pool 路径读取当前章节相关的标签文件。根据当前项目 CLAUDE.md 中的章节结构，动态生成 chapter-tag 映射表。核心章节（按 RQ 拆分的研究章节）对应 DISC-RQ{N} 标签，文献综述章对应 BG+LR 标签，绪论章对应 BG+GAP 标签。通用映射规则：

| 章节类型 | 应读取的 citation_pool 文件 |
|:--|:--|
| 绪论 | BG.md, GAP.md |
| 文献综述 | LR.md, METHOD.md, GAP.md |
| 研究设计/方法 | METHOD.md |
| 核心研究章（RQ{N}） | DISC.md (RQ{N} 子节) |
| 对策建议 | LR.md, DISC.md |
| 结论 | 无（改写为主，跳过本步骤） |

如 citation_pool 目录不存在 → 跳过本步骤，在对话中提示"建议先运行 /lit-workflow 生成引用池"。

**大文件分流策略**：citation_pool 各标签文件大小差异巨大（BG ~50篇、LR ~160篇、METHOD ~46篇）。当某个文件过大时，主 agent 无法一次性读取，需委托 subAgent 处理匹配。

判断规则：对每个需读取的标签文件，先用 Bash 统计文献数（`grep -c '| 核心\|| 重要\|| 备选' {file}`）：
- **≤ 60 篇**：主 agent 直接读取并匹配（GAP ~26、METHOD ~46、BG ~53 通常满足）
- **> 60 篇**：启动 subAgent 读取并返回匹配结果（DISC ~90、LR ~161 必定触发）

> **DISC.md 子节优化**：DISC.md 按 RQ 分为多个子节，动态检测 RQ 子节的行号范围（通过搜索 `## DISC-RQ{N}` 标题定位）。当章节映射只需某个 RQ 子节时，主 agent 用 Read 的 offset/limit 参数只读取对应子节即可，无需 subAgent。仅当需要完整 DISC.md 时（对策建议章）才触发 subAgent。

### 2.5.2 逐节匹配文献

对当前章每个三级标题，按内容来源类型处理：

- **改写 / 重组**：跳过（outline 的「参考段落」已足够）
- **本章小结**：跳过（基于已写内容合成，无需外部素材）
- **纯结构性新增**（研究内容全文地图、技术路线图描述等）：跳过（内容自衍生于论文结构）
- **新增（需素材）/ 展开**：执行文献匹配

匹配依据（双维度，优先级递减）：

1. **引用场景中的章节号**：citation_pool 引用场景已标注目标章节号（如"可在文献综述2.4.2节引用"），精确匹配当前 subsection 编号
2. **素材标签 + 主题关键词**：当引用场景无明确章节号时，使用 outline 中该节的「素材标签」字段定位 citation_pool 文件，再按写作要点中的核心概念与引用场景的内容描述匹配

匹配数量控制：每节 3-8 篇，按分级排序（核心 → 重要 → 备选）。

#### 大文件 subAgent 委托（当标签文件 > 60 篇时）

对超过 60 篇的标签文件，启动 subAgent（**run_in_background**，多个大文件可并行启动多个 subAgent）执行匹配。subAgent prompt 模板：

```
你是学术文献匹配专家。请从 citation_pool 标签文件中为学位论文各节匹配最相关的参考文献。

## 任务
读取 citation_pool 标签文件 `{FILE_PATH}`，为以下 subsection 各匹配 3-8 篇最相关文献。

## 需要匹配的 subsection

{逐节列出，每节含：}
### {编号} {标题} [{新增/展开}]
**写作要点**：
{从 outline 提取的写作要点}

---

## 匹配规则
1. **优先依据**：引用场景中明确提到的章节号（如"可在2.4.2节引用"），精确匹配 subsection 编号
2. **次要依据**：引用场景的内容描述 vs 写作要点的核心概念，主题关键词匹配
3. **数量**：每节 3-8 篇，核心 > 重要 > 备选
4. 同一篇文献可匹配到多个 subsection（如果引用场景覆盖多节）

## 输出格式

对每个 subsection，输出：

### {编号} {标题}

1. **{citation_key}** [{分级}] {作者} ({年份}). {标题}
   - 核心论点：{从引用场景提取}
   - 本节用法：{定义概念/支撑论点/提供证据/对比讨论}

2. ...

如某节无匹配文献，标注"无匹配"。
```

主 agent 收到 subAgent 结果后，与直接读取的小文件匹配结果合并，统一进入步骤 2.5.3 组装素材包。

> **为什么不拆分 LR.md 文件**：LR.md 是 lit-pool 阶段的产出物，按标签组织是其设计意图。拆分会破坏下游工具的兼容性。用 subAgent 读取是对上游产出的无侵入适配。

### 2.5.3 组装素材包

对每个匹配到文献的节，生成结构化素材：

**新增节的素材格式**：
```markdown
## X.Y.Z 三级标题 [新增]

### 应引用文献

1. **citation_key** [分级] 作者 (年份). 标题
   - 核心论点：{从引用场景提取该文献的核心发现/观点}
   - 本节用法：{在本节中如何使用——定义概念/支撑论点/提供证据/对比讨论}

2. ...

### 源项目可复用素材
- {可从 manuscript.tex 提取的相关数据/描述，标注行号}
- （如无可复用素材，标注"无"）

### 外部数据需求（仅行业背景类新增节）
- [ ] {需要查找的数据，如"国家统计局2023年建筑业增加值"}
```

**展开节的素材格式**：
```markdown
## X.Y.Z 三级标题 [展开 ← English §X.X]

### 英文原文已覆盖
- {英文论文在该主题上说了什么（1-2句概括）}

### 需要补充的内容
- {补充方向1}：推荐文献 → citation_key1, citation_key2
- {补充方向2}：需要 {详细推导/背景介绍/国内案例}

### 应引用文献

1. **citation_key** [分级] 作者 (年份). 标题
   - 核心论点：{从引用场景提取}
   - 本节用法：{补充英文原文未涵盖的哪个方面}

2. ...
```

### 2.5.4 保存素材文件

写入 `chapters/ch*_material.md`：

```markdown
# 第X章 章节标题 — 写作素材

> 生成时间：YYYY-MM-DD
> 数据来源：citation_pool/ ({N}篇匹配)
> 覆盖节数：{M}个新增/展开节

---

{逐节素材包，格式见 2.5.3}
```

**为什么用独立文件（不合入 outline）**：outline 保持简洁可审阅（用户交互用），material 可能较长（Ch2 素材可达 3000-5000 字）且不需要用户逐条审阅。

### 2.5.5 Git Checkpoint（素材文件）

素材准备完成后，material 文件单独作为一个 checkpoint：

> Checkpoint 卡：列出本步精确文件（建议提交信息 `diss-outline: ch{N} material prepared`），经 AskUserQuestion 单独确认后再执行 focused staging/commit；默认不 push（规格 §5）。

### 2.5.6 同步参考文献（master.bib → 项目 bib）

素材文件中引用的 citation key 必须在项目 bib 中可用，否则 `/diss-draft` 写入的 `\cite{}` 将无法编译。本步骤确保 bib 同步。

> **设计原理**：英文论文工作流中，`/analysis` Plan/Release 锁定方法引用与证据来源，`/narrative` 和 `/technical` 在写入 manuscript.tex 时验证并同步 bib。学位论文工作流中，`/diss-outline` 承担素材阶段的等价引用同步职责。

**执行逻辑**（幂等，多次运行安全）：

1. 检查 `{CITATION_POOL_PATH}/master.bib` 是否存在（`{CITATION_POOL_PATH}` 沿用 Step 0.4 解析结果——可能是本项目 `structure/2_literature/citation_pool/` 或源项目对应路径，**不硬编码本地路径**，否则走源项目 fallback 时会永远 WARNING）
   - 不存在 → WARNING: "master.bib 缺失，citation keys 可能无法解析。建议先运行 /lit-workflow"，跳过本步骤
2. 读取项目 bib 文件（从 CLAUDE.md 提取路径，通常为 `reference.bib`）
3. 提取项目 bib 中已有的所有 citation key（`@type{key,` 行）
4. 读取 master.bib 全部条目
5. 逐条合并：key 已存在 → 跳过；不存在 → 追加
6. 写入项目 bib
7. 统计输出：`bib 同步完成：新增 {N} 条，跳过 {M} 条（已存在），项目 bib 共 {T} 条`

> **为什么全量合并而非按需提取**：学位论文 100+ 引用 vs master.bib ~200 条，使用率 >50%。全量合并避免逐章追踪引用 key 的复杂性。biblatex 只输出实际 `\cite{}` 的条目，冗余条目不影响编译和参考文献列表。
>
> **改写节的隐性需求**：改写节没有 material 文件，但 sci-writer-zh 需要项目 bib 中的引用供选用。源项目文献在 lit-pool 步骤 0（`source_bib_to_pool.py`）已收录到 master.bib，全量合并一并解决此需求。

**Git Checkpoint**（含 bib 变更）：

> Checkpoint 卡：列出本步精确文件（建议提交信息 `diss-outline: sync master.bib → reference.bib ({N} entries added)`），经 AskUserQuestion 单独确认后再执行 focused staging/commit；默认不 push（规格 §5）。

如 bib 无变更（全部 key 已存在），跳过 commit。

## 注意事项

- **交互优先**：每章结构大纲（Phase 1）必须经用户确认后才保存，才进入下一章。不可批量生成后一次性展示
- **素材自动生成**：素材准备（步骤 2.5）在用户确认结构大纲后自动执行，不需要用户逐条审阅。如用户要求查看，展示即可
- **不写正文**：本 skill 只产出大纲要点（bullet points）和素材指引（引用谁 + 说了什么 + 怎么用），不写任何正文段落。正文由 `/diss-draft` 完成
- **要点粒度**：根据目标字数动态调整。参考标准：每 300-500 字一个要点（1000 字以下 3-4 条，1000-2000 字 4-6 条，2000 字以上 6-10 条）。每条要点 = 1 个核心论述点（1-2 句话描述），不是模糊的主题词
- **术语一致性**：同一英文术语在全文中必须使用统一的中文翻译，大纲阶段就要锁定
- **来源标注必须精确**：改写/展开类型必须标注英文论文的具体 section 编号和行号范围，不能含糊
- **参考段落完整引用**：改写/展开类型的参考段落必须引用 manuscript.tex 的原文，不能概述
- **章节类型规则不可省略**：步骤 1.3 中各章节类型的专属规则是硬性要求，不是建议
- **不修改章节骨架**：diss-init 确认的三级标题结构不可在本 skill 中修改。如果发现结构问题，提示用户重新运行 `/diss-init` 调整
