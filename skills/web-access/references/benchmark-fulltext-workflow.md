# Benchmark 全文获取与项目归档

适用于写作范文、reporting benchmark 和 design benchmark 的资料获取。由调用 skill 决定对标角色和阅读任务；本流程不改变其研究设计、正文写入或正式锁定规则。

## 自动发现与获取

1. 读取项目合同，定位已有 benchmark 目录、文献池和本地全文。复用符合当前任务的文件，避免重复下载。用户指定论文优先；缺少合适范文或候选仅有摘要时，主动补齐，不把“请用户找论文”作为默认下一步。
2. 通过 `web-access` 使用 OpenAlex 定向发现候选，再核对 DOI、期刊页面与文章身份。优先目标期刊、相同方法及相近研究问题，记录每篇的适用角色；被引数和期刊名称不能代替内容判断。遵循项目 OpenAlex 凭证规则，不输出密钥。已有精确 DOI 时可直接定位原文，不必重复搜索。
3. 默认沿用已验证流程：**检索定位 → 用户已登录的浏览器获取全文 → 下载并核验 → 命名并归档项目 → 阅读目标章节**。需要机构登录的出版商页面，直接使用现有 Chrome 登录态，通过 Computer Use 或 `web-access` CDP 打开论文、点击 View PDF/Download；不要反复用无登录态 fetch 判断论文不可得。公开作者库/机构库接受稿也是可用来源，但必须标明版本。
4. 下载按钮可能打开新 PDF 标签页，真正保存还需点击 PDF 阅读器的下载按钮并处理原生保存窗口。根据当次页面状态操作，不硬编码旧 tab ID、AX 索引、坐标或临时签名 URL。Computer Use 可操作浏览器和原生保存窗口；CDP 不可操作原生窗口时转用 Computer Use。
5. 仅当目标全文确实被登录或人工验证挡住时，请用户在现有浏览器完成该步骤；完成后继续原会话。可继续获取其他独立候选。无法获取的论文标为 `pending_fulltext`，记录具体阻碍，尝试公开作者库或合适替代论文；不能算作已读 benchmark。

## Downloads 只作中转

- 默认下载至 `~/Downloads/`，等待下载完成；`.crdownload`、登录页和只有摘要的文件不算全文。只处理本任务创建或用户明确指定的文件。
- 用 `pdfinfo`/PDF 解析器确认文件可打开、页数及元数据，再用 `pdftotext` 提取并核对标题、作者、年份、DOI和目标章节。版本或 DOI 无法核实时明确记录，不猜填。扫描 PDF 需 OCR 或逐页阅读；公式、矩阵或多栏提取失真时渲染相关页核对。
- 核验后以 `FirstAuthor et al. - Year - Short title - Journal - Version.pdf` 命名；单作者省略 `et al.`。版本使用 `published`、`accepted` 或 `submitted` 等经核实的标签。去除路径非法字符，保持标题可辨认。citation key 按项目规则另记，并检查现有 bibliography/manifest 的冲突。
- **沿用项目已有 benchmark 根目录与组织方式**，可新增日期/任务批次。无既有目录时使用 `<project>/structure/benchmarks/<YYYY-MM-DD>/<role>/`；`role` 如 reporting、design、narrative。不要在已有目录旁另建一套，也不要把全局 Downloads 或 `/tmp` 写成最终全文路径。
- 将本次新下载文件重命名并移动至该批次。目标重名时先比较 SHA-256：相同则复用，不同则按 DOI/版本区分，禁止覆盖旧全文。跨文件系统移动先复制并核验哈希，再移除本次下载源。用户原有 Zotero/其他资料库文件只复制或引用，不能因归档而移走。
- 提取文本与 PDF 同批次保存；临时渲染图可放 `/tmp`。移动后重新确认最终 PDF 可读且哈希一致，任务结束时报告项目内链接。

## 记录与阅读

复用已有批次清单；没有时创建轻量 `manifest.json`，每篇记录：citation key、标题/作者/年份/期刊、DOI、稳定来源页、获取日期与方式、版本、页数、项目相对 PDF/文本路径、SHA-256、候选角色、全文核验与目标章节阅读状态。不要保存 cookies、凭证或临时签名下载 URL。

下载核验和内容阅读是两个状态。从归档全文读完所需章节后，按调用 skill 提取章节顺序、段落任务、假设/收益/方程展开方式及对应 PDF 页码；不可凭摘要或目录声称已完成对标。完整 PDF 的存在也不等于模型正确。

检索、下载、命名、核验和归档属于 benchmark 获取任务，应主动执行到可审阅结果。资料状态可记为 `fulltext_verified`，但不等于作者已批准其作为正式 benchmark；设计/报告快照的 approved 状态、正文修改和 commit 仍按调用 skill 的既有边界执行。
