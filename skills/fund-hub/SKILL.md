# /fund-hub — 纵向项目总控

**规格**：`~/.claude/skills/shared/FUND-PROTOCOL.md`（下称"协议"）。

**输入** `$ARGUMENTS`：`status`（默认）| `check` | `assets` | `profile` | `backfill` | `remind`

除 `profile`、`backfill`、`remind` 外，本 skill 只读，不改任何文件（台账是生成文件，可以重新生成）。

## status（默认）

1. 运行 `python3 "$FUNDINGS/_scripts/build_portfolio.py"`，读 `PORTFOLIO.md`。
2. 输出，按紧急程度排序：
   - **进行中的项目**：申请人、基金、阶段、截止日期与剩余天数；30 天内截止的标 ⚠️
   - **每个项目的下一步**，按阶段：init → `/lit-plan` 或 `/fund-outline`；literature → `/lit-workflow`；outlining → `/fund-outline`；drafting → `/fund-draft`（列出状态不是"初稿"的章节）；polishing → `/fund-polish`；submitted → 等结果后 `/fund-result result`
   - **未来 90 天的申报窗口**：按 `_profiles/README.md` 的申报窗口推算，列出每个申请人可以申的基金（已在申或已立项的除外）。窗口标"待核"的提醒核对当年通知
   - **待补信息**中会影响判断的项（如申请人信息卡里的职称、在研课题为"待填"）
3. 不给超出台账内容的建议。

## check

全量合规检查，逐条输出"通过 / 不通过 / 无法判断（缺什么）"：

1. **命名**：PORTFOLIO.md 的"命名问题"；另查 `$FUNDINGS` 下不以 `_` 开头、又没有 FUND.md 的文件夹
2. **限项**：对每个申请人，读其本年度和下年度的所有在申项目，按各自档案的"合规与限项"逐条核对（同年度限报项数、在研项目冲突、成员参与上限、年龄与职称条件）。已立项项目也要算进"在研"
3. **跨申请人**：PORTFOLIO.md 的"跨申请人检查"。题目相近的，再读两个项目的 fund-idea.md 比较研究内容，给出"内容是否相近"的判断和依据
4. **成果归属**：每个进行中项目的研究基础章节，抽查成果是否都在对应申请人的成果清单里

只报告，不修改。

## assets

对每个申请人的 `_assets/{代码}/`：

- `成果清单.md` 头部"最后整理"日期超过 90 天 → 提醒更新
- 清单里 PDF 列写"缺"的条目 → 列出
- 状态写"已接收""在线发表"等过渡状态的论文 → 提醒核实是否已正式出版、卷期是否更新
- `申请人信息卡.md` 里的"待填"项
- 本人在已立项项目里，但成果清单"主持的科研项目"表里没有的 → 列出

只报告，不修改。

## profile

新建或更新基金档案。

1. AskUserQuestion：新建还是更新；基金简称（作为文件名，与项目文件夹名的第三段一致）。
2. 请用户给出官方文件（通知、申请书模板、活页、填报说明、常见问题），一般已放在某个项目文件夹里。
3. 提取文字：`.doc/.docx` 用 `textutil -convert txt -stdout`；`.pdf` 用 `pdftotext -layout`。扫描件提取不到文字时，在档案里标"通知为扫描件，以下待核"。
4. 按协议第 6 节写 `_profiles/{基金简称}.md`：头部字段（级别、交付类型、交付格式、匿名要求、申报窗口、立项名单系列——按协议第 9 节的系列表，表里没有就加一行；题目前缀——文科类填"常用"，自科类填"少用"）、正文结构（逐节标题和字数、页数限制，照抄原文标题）、合规与限项、评审要点、选题定位（如有）、来源文件。只写官方文件里有的内容，推断的标"待核"。
5. 更新：只改有变化的条目，在档案末尾加"更新记录：{日期} 按 {文件} 更新了 {哪些条目}"。
6. 同步 `_profiles/README.md` 总表的那一行。
7. 写入前展示全文，用户确认后再写。

## backfill

给缺卡片或命名不合规的项目补齐：

1. 找出 `$FUNDINGS` 下不以 `_` 开头且没有 FUND.md 的文件夹，以及 PORTFOLIO.md "命名问题"里的文件夹。
2. 对每个文件夹：读里面的文件名和可提取的文字，推断年度、申请人、基金、题目、阶段，生成 FUND.md 草稿（推断值加"（待核）"），命名不合规的给出合规名字。
3. 逐个展示，AskUserQuestion 确认后再写卡片；**改文件夹名单独确认**，并先检查有没有别的文件引用旧路径（`grep -rlF` 搜 `$FUNDINGS` 和 `~/.claude/skills`）。
4. 刷新台账。

## remind

把截止日期推到 TickTick。

1. 列出进行中项目的截止日期，以及计划在 90 天内开始的申报。
2. 每项建议两个提醒：截止前 4 周、截止前 1 周（已过的不建）。
3. 展示待建任务清单，**用户确认后**才用 TickTick 工具创建（工具未连接时，告诉用户并输出清单供手动添加）。
4. 不删除、不修改已有的 TickTick 任务。

## 注意事项

- 台账只能由脚本生成，不手改 PORTFOLIO.md。
- 跨申请人题目相近只是提示，由用户判断；但要把档案里的相关条款原文给用户看。
