# /fund-review — 基金申请书模拟评审

## 触发场景
用户需要对基金申请书（国自然、省基金、校级项目等）进行模拟评审，获取评分与修改建议。

## 工作流

### Step 0: 前置校验（不在此处改阶段）

开始时**不**更改 `## 项目阶段`。

理由：评审尚未完成就写 `reviewed` 会在用户 ESC 中断时留下错误状态；阶段转换应在"评审报告已落盘"的终点发生（见 Step 4.6）。

校验当前阶段是否为 `drafting`，非 `drafting` 时提示用户（仍允许继续，如用户坚持对草稿阶段的内容做前瞻评审）。

### Step 1: 读取申请书全文

- 确认基金类型（国自然青年/面上/重点、省基金、校级等）
- 从 `sections/` 目录读取各章节 md 文件（由 /fund-draft 生成）
- 如申请书为其他格式（Word/PDF/LaTeX），按对应方式读取

### Step 2: 主 agent 按基金专用 rubric 做评审

**强制**：进入独立的严厉基金评审口径，不受日常交流人设影响。必须逐项引用申请书证据并按下列 rubric 评分，不能用笼统评价代替审查。

```
review instructions:
  你是资深基金评审专家（见过数百份申请书），以严厉但建设性的方式审查下列基金申请书。

  基金类型: {FUND_TYPE}          # nsfc / provincial / university
  申请书正文源: sections/*.md（drafting/reviewed 阶段权威源；main.tex 仅为骨架占位，fund-polish Step 5.5 灌入后才含正文）
  Writing Brief: {BRIEF_PATH}     # 若存在则注入
  评审维度: （见下方对应表格）

  执行步骤：
  1. 读取申请书全文（含 Writing Brief 如存在）
  2. 按「{FUND_TYPE} 评审要点」逐条审查（见下表）
  3. 每个维度输出：评分 A/B/C/D + 评语（≥100 字，含具体行/段定位） + 修改建议（具体到段落/句子）
  4. 末尾给出「总体评价 + 综合评分 + 资助建议 + 最需改进的 3 个方面 + 亮点（如有）」

  评审风格要求：
  - 不说空话套话，每条评语必须有具体依据（引原文或定位行号）
  - 严厉但建设性——指出问题的同时给出改进方向
  - 特别关注：逻辑链条（"为什么做→做什么→怎么做→能做出来吗"）
  - 警惕常见通病：研究内容罗列而无逻辑、创新点空泛、技术路线图/文字脱节、立项依据综述与自己工作脱节
  - 时态/语气按基金文体（研究目标/内容用"拟"/"将"，已有基础用"已"/"已经"）
```

根据基金类型选择对应评审标准：

#### 国自然（NSFC）评审要点

| 序号 | 评审维度 | 审查要点 |
|:-----|:---------|:---------|
| 1 | **立项依据** | 科学问题是否明确？是否有重要科学意义或应用价值？国内外研究现状综述是否全面准确？拟解决的关键科学问题是否清晰？ |
| 2 | **研究目标与内容** | 研究目标是否明确、聚焦？研究内容是否围绕科学问题展开？各研究内容之间逻辑关系是否清晰？工作量是否适当（不过大也不过小）？ |
| 3 | **研究方案与可行性** | 技术路线是否清晰可行？研究方法是否恰当？实验/调研/建模方案是否详细具体？关键技术难点是否有应对策略？时间安排是否合理？ |
| 4 | **创新性** | 理论创新（新概念/新理论/新框架）？方法创新（新方法/新技术/新工具）？应用创新（新场景/新领域）？创新点是否与立项依据中的gap对应？ |
| 5 | **研究基础** | 申请人及团队前期成果是否与本项目相关？是否有足够的方法/数据/实验积累？发表论文质量和数量是否支撑本项目？ |
| 6 | **经费预算** | 预算总额是否合理？各科目分配是否与研究方案匹配？是否有明显不合理项（如设备费过高但无需购买设备）？ |

#### 省基金/校级项目 简化评审要点

| 序号 | 评审维度 | 审查要点 |
|:-----|:---------|:---------|
| 1 | **选题意义** | 是否有理论或实践价值？是否符合资助方向？ |
| 2 | **研究内容与方案** | 内容是否清晰？方案是否可行？ |
| 3 | **创新性** | 是否有一定创新？ |
| 4 | **研究基础** | 申请人是否具备完成能力？ |

### Step 3: 逐条评分与评语

对每个评审维度，输出：

```
### [维度名称]
- **评分**：A（优秀）/ B（良好）/ C（一般）/ D（较差）
- **评语**：（模拟真实评审专家风格，严厉但建设性，指出具体问题）
- **修改建议**：（具体到哪一段、哪一句需要改什么，给出改写方向或示例）
```

**评审风格要求**：
- 模拟见过数百份申请书的资深评审专家
- 不说空话套话，每条评语必须有具体依据
- 严厉但建设性——指出问题的同时给出改进方向
- 特别关注：逻辑链条是否完整（"为什么要做→做什么→怎么做→能做出来吗"）
- 警惕常见通病：研究内容罗列而无逻辑、创新点空泛、技术路线图有但文字没跟上、立项依据综述与自己的工作脱节

### Step 4: 总体评价

```
## 总体评价

### 综合评分：[A/B/C/D]

### 资助建议：[建议资助 / 修改后可资助 / 不建议资助]

### 总体评语
（3-5句概括性评价，模拟评审意见表中的"总体评价"栏）

### 最需要改进的 3 个方面
1. ...
2. ...
3. ...

### 亮点（如有）
- ...
```

### Step 4.5: 评审结果保存

将评审报告保存到 `reviews/fund_review_report_{日期}.md`，包含各维度评分、具体问题和修改建议。

```bash
mkdir -p reviews/
```

报告内容包含：
- 各维度评分（A/B/C/D）与评语
- 总体评价与资助建议
- 最需改进的 3 个方面
- 具体修改建议（精确到章节/段落）

### Step 4.6: 评审完成后更新阶段

在 Step 4 报告落盘后、Step 5 交互修改前执行：**`drafting → reviewed`**（若当前阶段为 `drafting`）。

> 单一责任方：`drafting → reviewed` 的转换由本 skill（/fund-review）负责；上游 /fund-draft 不要写 `reviewed`。

### Step 5: 交互式修改（可选）

- 用户可针对任一评审维度要求深入展开
- 用户可要求对特定章节进行修改示范
- 用户可要求以不同评审风格重新评审（如更严格/更宽松）

## 注意事项

- **不同基金类型标准不同**：国自然青年项目更看重申请人潜力和创新性；面上项目更看重研究基础和方案可行性；重点项目更看重系统性和团队
- **评审是主观的**：明确告知用户这是模拟评审，真实评审可能有不同偏好
- **保密意识**：不在评语中泄露或暗示可能的申请人身份信息
- **Be harsh but fair**：宁可现在被模拟评审打击，也不要等到真正评审时才发现问题
