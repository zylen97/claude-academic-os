# Profile: _generic（通用：未有专属 profile 的方法）

> 使用本文件时提醒用户"当前方法没有专属 profile"，但不停止流程。计划第 5 节由用户与主 agent 按该方法的领域惯例补齐，并在计划中注明依据的方法文献。

## 1 适用范围

上述专属 profile（saom / panel-regression / survey-sem / analytical-model）都不覆盖的方法，例如实验、案例研究的量化部分、ERGM、机器学习预测、DEA / SFA、系统动力学、混合方法。

## 2 输入（数据包 / 模型设定）

- 实证类：数据来源与版本、样本构建规则与各步样本量、变量定义与时点、缺失处理；`data/raw/` 只读，脚本在 `data/scripts/`，输出在 `data/results/`。
- 模型类：模型设定、假设、参数及其来源（若含推导，参照 `analytical-model` 使用 `structure/3_analysis/derivation/`）。
- 实验类另需：招募、分组、条件、操纵检查、排除规则、功效分析、预注册（如有）。

## 3 结论目标（效应 / 命题）

每个 RQ 写明要估计或证明的具体量（系数、差异、预测指标、效率值、命题），以及支持该结论所需的识别或推导条件。

## 4 证据类型

`data`｜`measure`｜`estimate`｜`proposition`｜`diagnostic`｜`robustness`｜`sensitivity`｜`null`｜`limit`｜`table`｜`figure`

## 5 必做检验

1. 输入完整性：样本量、缺失、取值合法。
2. 方法本身公认的有效性检验（由计划逐项列出并注明依据文献）。
3. 不确定性：标准误 / 置信区间 / 交叉验证 / 敏感性，按方法惯例。
4. 稳健性：计划登记的替代设定。
5. 空结果与失败检验进入登记表，不删除。

## 6 报告顺序

研究设计与数据（或模型设定）→ 变量 / 符号 → 方法与模型 → 主要结果（按 RQ）→ 有效性检验 → 稳健性。

## 7 解读边界

- 结论强度不超过设计所能支持的推断类型（关联 / 预测 / 因果 / 解析）。
- 样本或参数范围之外不外推。
- 不显著或失败的检验不改写为支持性证据。

## 8 空洞表述信号

- 只报数值或符号、不说明对研究对象意味着什么的句子；
- "the results are robust / satisfactory" 不说明依据；
- 用模型内部记号或变量缩写充当结论主语。
